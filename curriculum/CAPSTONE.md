# Capstone Requirements

Build a focused product for a clearly defined user. Prefer one reliable end-to-end workflow over many unfinished features.

## Required artifacts
1. Problem statement and target user.
2. Prioritized MVP scope and acceptance criteria.
3. Architecture or data-flow diagram.
4. Source code and meaningful commit history.
5. Setup instructions and safe configuration example.
6. Tests or a documented manual verification plan.
7. Accessibility, privacy, and security considerations.
8. Demo script and screenshots/recording where appropriate.
9. Known limitations and next-step backlog.
10. Reflection on AI assistance and independent verification.

## Review checklist
- [ ] Fresh setup instructions work.
- [ ] Primary user journey is demonstrable.
- [ ] Invalid, empty, and failure states are considered.
- [ ] Test results are recorded accurately.
- [ ] No secrets or personal data are committed.
- [ ] README claims are backed by evidence.
- [ ] Dependencies and license assumptions are documented.
- [ ] Learner can explain architecture and trade-offs.

## Five-minute demo
Problem and user (30 sec); product walkthrough (2 min); architecture (1 min); verification evidence (45 sec); limitations and next steps (45 sec).
