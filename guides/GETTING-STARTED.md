# Getting Started with Vibe Coding

This guide is for someone who is new to building software with AI. You do not need to know everything before starting—but you should understand and test what you build.

## What is vibe coding?

Vibe coding is an iterative way to build software by describing what you want in everyday language and working with an AI coding assistant. You provide the idea and direction; the AI can help plan, write, explain, and debug code. You still need to review the result and check that it actually works.

## What you need

- A computer and a modern browser.
- A code editor such as VS Code.
- Access to an AI coding assistant you are allowed to use.
- Git and a GitHub account when you're ready to save and share your work.
- Patience to test, debug, and make small improvements.

Tool names and interfaces change, so learn the workflow rather than depending on one particular AI product.

## Your first working session

1. Pick one small outcome, such as a personal links page.
2. Describe the intended user and behavior in a few sentences.
3. Ask the AI to suggest a short plan before generating code.
4. Ask it to explain the files and how to run the project.
5. Build one part at a time.
6. Run the project locally and try it yourself.
7. If something fails, share the exact error and ask for an explanation before requesting a fix.
8. Review the changes and write down one thing you learned.

## A prompt you can reuse

> I am a beginner. Help me build [small project] for [target user]. First ask questions if anything important is unclear. Then give me a short plan and explain which files you expect to create or change. Build only the first small step. Explain how I can run it and verify it before we continue. Keep the solution simple and do not add features I did not request.

## Good habits

- Ask for explanations, not just code.
- Give specific requirements and examples of expected behavior.
- Change one thing at a time.
- Run the app after meaningful changes.
- Check error cases, not only the happy path.
- Keep a working version before attempting a large refactor.
- Never paste passwords, API keys, private messages, personal records, or confidential code into an AI tool.
- Do not run commands you don't understand, especially commands that delete files or change system settings.
- Never claim a feature or test works unless you verified it.

## When you get stuck

Use this sequence:

1. Reproduce the problem.
2. Copy the exact error message.
3. Tell the AI what you expected and what happened.
4. Ask it to explain the likely cause and propose the smallest fix.
5. Apply the fix and repeat the same test.
